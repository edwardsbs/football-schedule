# Kickoff Punch List

## Queued

- [ ] **Retro Football (NES Tecmo Super Bowl) — in progress, ROM loading works on the KTC tablet, audio-drift fix and Bluetooth button remap just added and awaiting a real test.** Scope: exactly one cartridge, no ROM picker menu — selecting it from the Mini-Games hub goes straight to Tecmo Super Bowl. Done: mapper confirmed as MMC3 (mapper 4) from the ROM's own iNES header; **NesJs** (MIT) chosen and vendored into `kickoff-client/public/nesjs/` (loaded on demand by `NesjsLoaderService`, never in the eager bundle); a real `RetroFootballComponent` at `/games/retro-football` runs the canvas/audio loop, ROM loaded via a local file picker (never bundled, fetched, or committed — `ROMs/`/`*.nes` are gitignored since this repo is public on GitHub). **Confirmed working on the actual KTC tablet inside Fully Kiosk Browser** after buying Fully Kiosk's PLUS license and enabling "Enable File Upload (PLUS)" — boots, plays, file picker opens fine. Bluetooth controller reads via Gamepad API polling (D-pad/left stick → movement, A/B/X/Y → NES A/B, Back → Select, Start → Start) with a connected/not-connected badge, plus the keyboard handler swallows every key while a game runs so a pad's synthesized keys can't leak into Fully Kiosk's own navigation. Added a persisted **Swap A/B** button next to Pause/Reset since two of the user's controller buttons came out backwards and there's no remapping option in Fully Kiosk itself. Audio was popping on both the laptop and the tablet — first widened NesJs's ring buffer (4096→16384 samples, `kickoff-client/public/nesjs/js/audio.js`), which only delayed the pops rather than fixing them, since the real cause was `requestAnimationFrame` (tied to the display) driving audio generation against the audio hardware's independent, steadier clock — a persistent, non-jitter drift that any fixed buffer size eventually catches up to. Real fix: `AudioHandler` now exposes a `stepCallback` that its audio callback pulls on its own clock to step the emulator on demand (`nes.runFrame()` moved out of the rAF loop entirely); rAF now only repaints the canvas from whatever frame the emulator most recently finished. Documented both audio.js patches in `kickoff-client/public/nesjs/README.md` since the file is no longer bit-for-bit upstream. Verified with `tsc --noEmit` and a production `ng build` (both clean) but **none of this — button swap, audio fix — has been heard/felt on a real device yet**; that's the next thing to confirm. Remaining after that: on-screen touch controls (backup when the controller isn't at hand), save states, and the visual kiosk reskin. Full plan: see the "Retro Football Emulator" artifact from this project's planning session.

Also visually fades the whole rail from 55% opacity at kickoff up to full strength by Week 8 (real NFL records don't separate from one-score-game noise until roughly the season's halfway point, per Football Outsiders-style analytics), with a matching footer note that disappears once maturity is reached — a smooth transition, not a jarring on/off flip.
